## Before you start

This practical track is for engineers building cloud and DevOps skills. You should be comfortable with a Linux terminal, basic TCP/IP and Git. Each module lists its own prerequisites; no particular certification is required. Work through the labs in order, or use an individual module as a reference.

## How to work through the track

Follow the ordered modules below. Each includes objectives, prerequisites, English technical explanations, Arabic takeaways, labs, validation, cleanup, troubleshooting, senior interview answers and a short interactive quiz. Mark completion after collecting evidence. Progress is saved locally and synchronizes through the existing account sign-in; the original platform tour and its progress remain available.

Use a dedicated sandbox account/subscription. Read commands before running them, set a budget alert and destroy deadline, and never use this repository's production infrastructure or database. Local validation is separate from paid cloud deployment. Quizzes provide feedback; completion is an honest self-assessment rather than a certification.

## Track outcomes

Draw and diagnose a two-AZ AWS network; defend least-privilege federation and runtime secrets; operate ALB/ASG and recovery; review remote-state drift; and deploy/tear down the WordPress capstone. Collect a resource plan, packet/identity diagram, incident timeline, restore runbook and cost estimate.

The capstone requires an issued ACM certificate, matching DNS hostname and a reviewed WordPress release/hash. It creates paid infrastructure only when you explicitly apply it. [Capstone lab files](../labs/aws-wordpress/README.md).

## Practice, explain and adapt

Use a five-minute architecture explanation and a ten-minute incident walkthrough. Distinguish what you built, what you measured and what you would change. For any real deployment, check its data-residency requirements, regional service/SKU availability, latency and disaster-recovery region options. Do not assume all customers must use a particular region or that a demo proves regulatory compliance. Recheck current service availability/pricing before every paid lab.
