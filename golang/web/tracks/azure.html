Before you start

This practical track is for engineers building cloud and DevOps skills. You should be comfortable with a Linux terminal, basic TCP/IP and Git. Each module lists its own prerequisites; no particular certification is required. Work through the labs in order, or use an individual module as a reference.

How to work through the track

Follow the ordered modules below. Each includes objectives, prerequisites, English technical explanations, Arabic takeaways, labs, validation, cleanup, troubleshooting, senior interview answers and a short interactive quiz. Mark completion after collecting evidence. Progress is saved locally and synchronizes through the existing account sign-in; the original platform tour and its progress remain available.

Use a dedicated sandbox account/subscription. Read commands before running them, set a budget alert and destroy deadline, and never use this repository's production infrastructure or database. Local validation is separate from paid cloud deployment. Quizzes provide feedback; completion is an honest self-assessment rather than a certification.

Track outcomes

Build an Azure scope/identity map; trace private DNS, routes and data roles; choose L4/L7 ingress and compute scaling; operate remote state and federation; and diagnose the private application capstone. Guided Azure CLI examples make the track accessible to engineers new to Azure, including those moving from another cloud.

The capstone is a single private app VM behind an internal load balancer, with optional probe VM, private Blob endpoint and managed identity. It teaches security and diagnosis; VMSS and Application Gateway have optional practical extensions in the compute module. Capstone lab files.

Practice, explain and adapt

Use a five-minute architecture explanation and a ten-minute incident walkthrough. Distinguish what you built, what you measured and what you would change. For any real deployment, check its data-residency requirements, regional service/SKU availability, latency and disaster-recovery region options. Do not assume all customers must use a particular region or that a demo proves regulatory compliance. Recheck current service availability/pricing before every paid lab.

  1. 1. Azure operating model: subscriptions, Entra ID and RBAC70 min · Not completed

  2. 2. Azure networking: NSGs, routes, private endpoints and DNS85 min · Not completed

    Trace effective routes and NSGs, distinguish private endpoints from service endpoints, and diagnose private DNS from the workload.

  3. 3. Azure compute: VMs, scale sets and load-balancing choices75 min · Not completed

    Choose L4 versus L7 ingress, inspect private VM health and explain VMSS rollout, probes and availability choices.

  4. A good point to pause

    You have worked through several boundaries. Take a short break, then explain one of them without your notes. Return to any check you cannot yet reproduce.

  5. 4. Azure services: Storage, Key Vault, identities and Monitor85 min · Not completed

    Trace VM managed identity to private Blob access, distinguish Key Vault network and role failures, and collect useful operating signals.

  6. 5. Azure Terraform: provider identity and Blob remote state80 min · Not completed

    Separate provider and backend authentication, use Entra-authorized state, and recover safely from drift and orphaned Blob leases.

  7. 6. Azure delivery: federated GitHub Actions and Azure Pipelines75 min · Not completed

    Configure workload federation in both CI systems, protect service connections, and separate preview from approved apply.

  8. The pieces are coming together

    Keep your notes and evidence close. The capstone is a chance to connect what you have practised, one verified step at a time.

  9. 7. Azure capstone: build and diagnose a private application130 min · Not completed

    Build a private VM application behind an internal load balancer, authorize private Blob access through managed identity, and diagnose DNS, process and RBAC failures.
